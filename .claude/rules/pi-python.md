# Python на Pi

- **Python 3.11.** На Pi venv `~/maze/venv`, без API версий 3.12+ (`type X = ...`, `itertools.batched`, новый синтаксис f-строк и т.п.).
- **Новых зависимостей не добавлять** без вопроса: `pip install` в этот venv может незаметно сломать камеры. Сначала стандартная библиотека и то, что уже стоит (numpy, opencv, picamera2).
- **Тесты:** `python3 -m unittest discover -s pi/tests` (≈0,5 с), пропуски «нужен numpy» — норма. Тест на новую логику кладётся в `pi/tests/test_<модуль>.py`, без железа.
- **Модуль:** первая строка docstring — что он делает (из неё строится `docs/CODEMAP.md`). Константы модуля — вверху модуля, общие — в `config.py`, общее состояние — `state.x`.
- **В новом коде** вызывать соседние модули как `модуль.функция()`: по имени видно, в каком файле искать. Старые `from x import …` не переписывать.
- **В новом коде ошибки железа не глотать:** без `except: pass` и `except Exception: return 0` — обработать по смыслу (ждать, повторить, показать на дашборде) или пробросить; значение по умолчанию при сбое датчика видно в логе. Старые `except Exception` трогать только в рамках задачи.
- **Временные скрипты и отладочные выводы** не оставлять в `pi/`: временное — в scratchpad, отладочный `print` убрать до слов «готово».
