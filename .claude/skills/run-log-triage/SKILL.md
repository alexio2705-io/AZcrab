# Разбор лога заезда (MAZE2027)

Вставка в чат обычно обрезана. Сначала — полный лог: `~/maze/run_ЧЧММ.log` на Pi
(забрать через pi_connect в scratchpad), рядом `wall_debug.log`, `map_web.log`,
`dash_web.log`, `nav_hup.log`. Искать **первую** аномалию, а не последнюю:
дальше обычно её следствия. Причину подтверждать (**REQUIRED SUB-SKILL:**
superpowers:systematic-debugging), а не чинить по догадке. Симулятор не
используется: подтверждать по логам, юнит-тестом на чистую функцию или
следующим заездом с понятным «на что смотреть».

## Как читать строки nav.py

| Строка | Что значит |
|---|---|
| `─── (x,y) N → E  k/N ───` | шаг: клетка, курс сейчас → куда, разведано k из потолка N. `y ≥ 1000` — верхний этаж (`LEVEL_STRIDE`=1000: `(0,1003)` = этаж 1, y=3) |
| `кл.K ост. Nмм yaw=…(e=±) we=a→b° spd=V` | езда по плану: клетка K, осталось мм, ошибка курса, поправка по стенам (мм → °), скорость см/с |
| `→ кл.(x,y): R=есть(Nт,Mмм) L=… F=нет(a:b) → прямо/стоп` | стены на ходу: т — точек лидара, мм — дистанция; F — голоса «есть:нет» |
| `[odo] столбик right у границы кл.K: ±N - цель ±M` | поправка одометрии по краю стены |
| `торможение …`, `у стены: f=…`, `[выр N] F/B=… назад/вперёд` | доводка у стены; `[выр] не по стене` — стена ближе одометрии (препятствие?) |
| `поворот ±90° цель=…` / `итог yaw=… ошибка=… за Tс TURN_FF=…` | поворот на месте и его точность |
| `препятствие #N: pitch=… момент …A`, `БАМПЕР (left/right/both)`, `шаг вбок` | препятствия и концевики |
| `горка: …мм по уклону (~n плит.)…`, `⛰ ГОРКА вверх: ~n плит., A → B, этаж` | горка и сколько клеток ей засчитано |
| `⏱ Tс: ход, поворот, лидар` | на что ушло время шага (простой ищется здесь) |
| `↩ Возврат на старт`, `✓ На старте` | конец заезда (единственный законный) |
| `[WAIT]`, `[WARN]`, `[подъём?]`, `[VD]`/`[VW]` | ожидание связи/моторов, предупреждения, детектор подъёма, зрение |
| старт: `YAW_ORIGIN=…`, `калибровка белой: C=… (порог чёрной …)`, `плитка=…` | опоры курса и цвета |

`telem.py`: строка 5 раз/с, `>>>` — смена кнопки/концевика; `0Гц` или «жду пакеты N байт
версии V» — ESP молчит или разный `TELEM_VER`. `color.py`: канал около 10250 — насыщение.

## Уже встречалось — проверить первым

| Симптом | Частая причина | Чем подтвердить |
|---|---|---|
| стены там, где их нет | леска ручки в 3–7 см от лидара; кирпичи; наклон на горке/препятствии | робот на открытом месте (30 см без стен), `raw_scan.py -n 30`, `wall_debug.log` |
| перестал видеть стены | фильтр ручки/шума после правки стал слишком строгим | тот же `raw_scan.py` у реальной стены, сравнить с прошлой версией |
| проехал лишнюю клетку, карта съехала | недоезд на 2-мм профилях/препятствиях, не доехал до передней стены | строки `кл.K ост.`, `[odo]`, `у стены` у этой клетки |
| горка = 4 клетки / не та длина | длина по уклону и высота в строке `горка:` | сравнить с реальной горкой |
| трясёт на повороте | выход из застревания или поворот на препятствии | строки поворота и `препятствие` рядом |
| «сняли с поля» ложно / не срабатывает | пороги ускорения; быстрая езда похожа на подъём | `lift.py` с подъёмами и прокатом по полу |
| чёрная не видна, зеркальная = белая | калибровка с не той плитки, насыщение | `color.py 3` на каждой плитке, `tile_calib.py` |
| кнопка не реагирует | дважды оказывалась мёртвая кнопка | `telem.py` (`>>>`), прозвонка |
| метка не та / не замечена | свет, частично в кадре, цвета колец | `victim_web.py` (:8000, /tune), кадры в `~/maze/detections` |
| камеры падают на старте | pip обновил numpy в venv | `from picamera2 import Picamera2` в venv |

## Правила, которыми мерить лог

- Заезд кончается только на старте. `[FATAL]`, выход посреди поля, «не могу вернуться» — это ошибка навигации, а не допустимый исход. Моторы/связь пропали — ждать и показывать фазу на пульте.
- Комплекты выдаются сразу у жертвы.

Ответ пользователю: что видно в логе (с цитатой строки), какая гипотеза, чем её
проверить на роботе — одна команда для его SSH-сессии (pi_connect).
