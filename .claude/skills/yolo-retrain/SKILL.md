# Переобучение YOLO меток (MAZE2027)

Всё обучение — в `~/maze_dataset` (не в репозитории), Python — `~/maze_dataset/venv/bin/python`.
История решений и цифры моделей B/C/C2/C3: `docs/model_C_report.md` — читать перед работой
и дописывать после.

## Классы — не переименовывать

`0 cognetive, 1 omega, 2 phi, 3 psi` — жертвы (код на Pi ищет их **по имени**);
`4 H, 5 S, 6 U, 7 letter` — приманки, робот их отбрасывает (`watch_logic.victim_boxes`).
Новый класс — только в конец и с правкой `watch_logic`/`victim_detect.py`.

## Данные

| Папка | Что |
|---|---|
| `ds_own`, `raw` | свои кадры с робота (сбор: `pi/dataset_web.py` на Pi, :8000) |
| `ds_ext`, `ext*`, `rf_v1` | чужие датасеты Roboflow (`rf_get.py`, ключ читается из файла — не печатать его) |
| `ds_synth2` | синтетика `synth_letters.py`: приманки **и** жертвы, нарисованные одним генератором |
| `ds_v2`, `ds_v3` | сборки для обучения (`build_ds_v2.py`; `ds_v3 = ds_v2 + ds_synth2`) |

Ловушки, на которых уже обжигались:
- **Короткий путь.** Если всё нарисованное — приманки, а все жертвы — фото, модель учит «нарисовано → приманка». В синтетике должны быть и жертвы (`VICTIM_P`).
- Настоящая Φ/Ψ/Ω не должна попадать в приманки при вклейке — проверять листами (`sheet.py`) глазами.
- Метка не совпадает с папкой-источником — `reports/label_suspects.txt`, `fix_labels.py`.

## Обучение

- Мак (M4 Pro, MPS): дообучение от лучших прошлых весов, `imgsz=320`, `degrees=45, flipud/fliplr=0.5`. Образец — `train_c3.py`. Около 90 кадров/с; `workers` и батч 64 не ускоряют — не тратить на это время.
- Долго (>1 ч) — Google Colab T4: `colab/train_c3_colab_v2.ipynb`, результаты на Диске `maze_colab/runs/<имя>`. Нужен Chrome пользователя и его Google-аккаунт: вход и разрешения делает он сам.
- Запуск в фоне через `nohup … > train_<имя>.log 2>&1 &`. Живой монитор: `train_monitor.py` (конфиг `train-monitor` в `.claude/launch.json`, :8792) — потери, метрики и приманки по эпохам.

## Как решить, лучше ли новая модель

Сравнивать с текущей таблицей в отчёте, по всем пунктам сразу:

```bash
cd ~/maze_dataset && venv/bin/python eval_decoys.py models/maze_v26n_<X>.pt ds_v3
```

1. Приманки, названные жертвой (порог 0.45, как на роботе) — должно быть ≈0.
2. Найдено Φ/Ψ/Ω на валидации `ds_v3`.
3. Свои кадры с робота: Φ/Ψ/Ω/цели из 50.
4. Нарисованные жертвы (проверка короткого пути).
5. Живьём на камере Мака: `venv/bin/python webcam_test.py models/<X>_ncnn_model 0` (конфиг `webcam-test`, :8793).

Хуже хоть по одному пункту — сказать прямо; не ставить на робот без решения пользователя.

## На робот

```bash
cd ~/maze_dataset && venv/bin/python -c "from ultralytics import YOLO; YOLO('models/maze_v26n_<X>.pt').export(format='ncnn', imgsz=320)"
```

- На Pi: `~/maze/models/maze_v26n_<X>.pt` и папка `maze_v26n_<X>_ncnn_model/` рядом (NCNN подхватывается сам, ~28 мс против ~90 у PyTorch). Копировать — через pi_connect, папку — `scp -r`.
- Пробный заезд с новой моделью: `MAZE_MODEL=<X>` перед командой `nav.py`. Модель по умолчанию — буква в `YOLO_MODEL_PATH` в `victim_detect.py`; менять после проверки на поле.
- Проверка на поле: чужие буквы (Q, O, U, S, H, кириллица) рядом с настоящими метками; остановок на них быть не должно. Кадры из `~/maze/detections` — материал для следующего дообучения.
- Ничего не ставить через `pip` в venv на Pi без `--no-deps` (ломает камеры).
