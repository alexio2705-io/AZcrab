# Работа над проектом

Прочитай и соблюдай действующие проектные инструкции в [CLAUDE.md](CLAUDE.md).

## Координация GPT-6.1 Terra

1. Для каждой задачи координатор выделяет от одного до трёх независимых поручений. Например, одному исполнителю поручает разобрать логику управления, другому проверить тесты, третьему изучить пограничные случаи. Каждый исполнитель Terra выполняет только своё поручение в режиме чтения. Делегированием и правками занимается координатор.
2. Создай отдельную папку запуска в `.cache/terra/`. Для каждого поручения запиши цель, границы работы и ожидаемый результат в отдельный файл. Попроси указать файлы, функции и строки, по которым можно проверить выводы.
3. Запускай поручения параллельно из корня проекта. Для каждого процесса задай свой `task_file` и свой новый `result_file`. При каждом запуске Terra используй локальный Codex CLI с профилем второго аккаунта:

   ```sh
   CODEX_HOME="$HOME/.codex-terminal" codex exec -m gpt-6.1-terra --sandbox read-only -o "$result_file" - < "$task_file"
   ```

   Если папка проекта вне рабочего дерева Git, добавь `--skip-git-repo-check` перед завершающим `-`.

4. Дождись каждого процесса. Проверь код завершения и убедись, что каждый файл результата непуст и отвечает на соответствующее поручение. При повторе используй новый путь результата и тот же профиль.
5. Сверь выводы с текущим кодом и тестами. При расхождениях проверь спорное место самостоятельно. Координатор вносит и проверяет согласованные правки в рамках запроса пользователя. Для задач только на анализ достаточно проверенного отчёта.

## Поручения исполнителям

Профили Terra лежат в `.agents/terra/`. Для каждого выбранного исполнителя скопируй содержимое его профиля в отдельный `task_file` и допиши конкретный запрос, контекст пользователя и границы проверки. Передавай получившийся файл через stdin командой выше. Если Terra уже получила такое поручение, она отвечает сама, без повторного запуска команды.

- [Логика управления](.agents/terra/control.md) прослеживает манёвр от измерения до команды или изменения состояния.
- [Тесты](.agents/terra/tests.md) проверяют, какая ветвь покрыта и какой пример воспроизводит пропуск.
- [Пограничные случаи](.agents/terra/edges.md) проверяют порядок событий, граничные значения и состояние при повторе.

## Скиллы для задач о заезде

- [maze-run-compare](.agents/skills/maze-run-compare/SKILL.md) — сравнить время на клетку и число повторных действий по полевым логам.
- [maze-pose-review](.agents/skills/maze-pose-review/SKILL.md) — найти, где после наклона или препятствия разошлись положение робота и запись в карте.

Если скилл нужен исполнителю, включи путь к нему в поручение. Для разбора первой аномалии в логе и проверки после изменения кода используй существующие инструкции в `.claude/skills/run-log-triage/` и `.claude/skills/maze-verify/`. При работе с Pi или ESP открой соответствующий файл в `.claude/rules/`.
