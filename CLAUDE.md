# MAZE2027

Робот для RoboCup Junior Rescue Maze. ESP32-S3 (ESP-IDF, `src/`, `include/`) управляет моторами и датчиками, Raspberry Pi 5 (`pi/`) ведёт навигацию по лидару LD19, читает метки жертв (YOLO) и цвет плиток, показывает дашборд и OLED. `sim/` — симулятор, гоняет настоящий `pi/nav.py` на модели железа.

Общаться с пользователем по-русски.

## Правила, которые пользователь сказал прямо

- **Заезд кончается только на старте.** В `nav.py` нет аварийных выходов (`FATAL`). «Старт недостижим по карте» — всегда баг навигации. Если моторы или связь с ESP пропали, ждать и показывать это на дашборде (`pi/dash_web.py`), а не выходить.
- **Никаких «отключающих» исправлений.** Не лечить баг флагом или константой, которая выключает фичу (`--no-ramps` и подобное). Код должен работать на любом поле, с включёнными горками.
- **Робот всегда решает.** Нет итогов вида «не знаю» (цвет плитки, метка). Если прямое чтение неоднозначно, брать контекст: гироскоп (pitch/roll), соседние плитки, второй датчик, и выбирать самый вероятный вариант.
- **Аптечки выдаются сразу у жертвы.** Не откладывать до конца обхода лабиринта, даже если симулятор считает очки лучше.
- **YOLO только в сторону стены.** Читать метки лишь камерой, у которой с её стороны есть стена (фронтальная тоже). Пока фронтальная камера читает цвет пола, YOLO на ней не работает.
- **Технические испытания неактуальны.** Не трогать `pi/challenge.py`, `pi/letters_cv.py`, `docs/tech_challenges.md`.

## Как работать

- **Проверять на роботе, а не в симуляторе.** Симулятор гонять только по просьбе. После правки: компиляция, быстрые юнит-тесты, заливка на Pi, дать команду запуска. Симулятор прошёл новую навигацию, а на поле она ехала плохо.
- **Базовая навигация — версия от 7 октября** (ветка `nav-oct7`). Правки минимальные и читаемые. Новую логику с ветки `victim-watch` переносить по одной фиче. За начало отсчёта углов брать нулевое положение при старте, не изучать наклон IMU глубже.
- Не запускать многошаговые эксперименты с железом (отладочные прошивки, калибровки) без вопроса.
- Для работы есть проектные скиллы: `maze-verify`, `esp-flash`, `pi_connect`, `run-log-triage`, `session-handoff`, `yolo-retrain`.

## Железо и поле

- Лидар на высоте 13 см, стены 15 см. Уже около 4° наклона лидар видит поверх стены.
- Горки 25–30°, любой длины. На них нет жертв, цветных плиток и препятствий. Каждая горка меняет высоту ровно на один уровень. На один остров могут вести горки разной длины. Ступеньки до 2 см тоже могут менять уровень.
- Pi: пользователь `madness`, лидар на `/dev/ttyAMA3`, venv `~/maze/venv` на Python 3.11 (без API версий 3.12+). `pip install` в этот venv может незаметно сломать камеры.
- Перед заливкой сравнить файлы на Pi с локальными и сделать `.bak`.

## Проверка и инструменты

- `python3 -m unittest discover -s pi/tests` (≈0,5 с). Пропуски «нужен numpy» — норма.
- Хук в `.claude/settings.json` сам гоняет эти тесты после правки `.py` в `pi/` и не даёт править `compile_commands.json` и `sdkconfig.*` вручную.
- `compile_commands.json` обновлять командой `pio run -t compiledb`.
