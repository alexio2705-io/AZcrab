3. Нет агента, который ищет проглоченные ошибки (`esp_err_t` без проверки, голый `except`, тихие значения по умолчанию у датчиков).
4. Нет шага «оценить влияние» перед правкой протокола ESP↔Pi или общего кода навигации.
5. context7 сломан, документацию ESP-IDF модель берёт по памяти.

## 2. Что полезного в everything-claude-code (Affaan Mustafa)

Репозиторий: 71 агент, ~310 скиллов, 98 команд, правила для 20 языков, 27 хуков, 38 MCP в примере конфига. Почти всё про веб, бизнес и другие языки. Хуки написаны на Node и завязаны на их установщик, поэтому брать **идеи**, а не файлы.

Стоит взять (в адаптированном, коротком виде):

| Что | Зачем тебе | Как адаптировать |
|---|---|---|
| Агент `silent-failure-hunter` | Ищет проглоченные ошибки, опасные значения по умолчанию, потерю ошибки по дороге | Переписать под C/ESP-IDF и Python: `ESP_ERROR_CHECK` против игнора, `except: pass`, датчик молча вернул 0 |
| Скилл `change-impact` | Перед правкой: кто вызывает, какие форматы и тесты затронуты; после: сверка diff с планом | Короткая версия: протокол ESP↔Pi, `nav.py`, дашборд, тесты |
| Правила с привязкой к путям (`.claude/rules/*.md` с `paths:`) | Правила для C грузятся только при работе с `src/`, для Python только с `pi/` | Вынести из `CLAUDE.md` разделы про ESP-IDF и Python 3.11 |
| Идея `strategic-compact` | Подсказка сжать контекст на границе этапа, а не посреди задачи | Маленький Python-хук по размеру контекста, или просто правило в `CLAUDE.md` |
| Принцип «отключай неиспользуемое» | Меньше шума в выборе скиллов | Отключить gstack или оставить 3–5 нужных скиллов |

Не брать: `gateguard` (711 строк, блокирует каждую первую правку), `continuous-learning-v2` (дублирует память), общие C++-правила (они про десктопный C++17, а не про C на ESP-IDF), десятки языковых ревьюеров.

## 3. Что нашлось на GitHub

**Большие коллекции** (anthropics/skills ~188k★, awesome-claude-code ~57k★, wshobson/agents ~42k★, VoltAgent subagents ~26k★, ComposioHQ и travisvn awesome-claude-skills): embedded, ESP-IDF и Raspberry Pi там почти нет. Годятся как образцы формата.

**Embedded-скиллы**

- `esp32-expert` (mathisk2095/jko-claude-plugins): содержимое хорошее (слои железо → RTOS → логика → язык; ISR без блокировок, `IRAM_ATTR`, DMA не в PSRAM, `vTaskDelayUntil` вместо `vTaskDelay` для периодических задач, `ESP_RETURN_ON_ERROR` вместо `ESP_ERROR_CHECK` в рабочих путях). **Но README репозитория предлагает скачать zip и запустить его от администратора с обходом предупреждений Windows. Это признак вредоносной подмены.** Не ставить. Идеи взять в свой чек-лист.
- ESP-IDF-скиллы на агрегаторах (smithery, claudskills, openskillindex): сгенерированы автоматически, местами пустые заглушки.

**MCP-серверы**

- `Adancurusul/embedded-debugger-mcp` (213★): отладка через probe-rs. На Xtensa (S3) регистры PC/SP по README неверные. Пока сырой.
- `oraios/serena` (31k★): семантический поиск по коду через LSP. Для C на ESP-IDF поддержка не заявлена, а clangd и pyright у тебя уже стоят как плагины. Не нужен.
- `github/github-mcp-server` (официальный, 34k★): у тебя есть `gh`, этого хватает.
- `I-CAN-hack/pdf-mcp` (82★): постраничное чтение PDF с поиском. Встроенный Read уже читает PDF по страницам. Не нужен.

Вывод: под твой стек готового хорошего почти нет. Выгоднее усилить свои скиллы и агентов, чем тянуть чужие.

## 3а. Общие практики: код, структура, токены, карты (из ECC)

**Принципы из правил ECC (`rules/common/coding-style.md`)**: KISS, YAGNI, DRY только для настоящих повторов; много маленьких файлов вместо больших (обычно 200–400 строк, мягкий потолок 800); функции до 50 строк; вложенность не больше 4 уровней, ранний `return`; именованные константы вместо «магических чисел»; ошибки не глотать; делить по фичам, а не по типам файлов.

**Токены (длинный гайд автора)**
- Главный рычаг — субагенты на самой дешёвой модели, которой хватает. Haiku для поиска и простых правок, Sonnet для обычного кода, Opus для архитектуры и сложной отладки. У тебя это уже есть.
- Модульный код с файлами на сотни строк, а не тысячи, экономит токены и чаще получается с первого раза.
- MCP, которые просто оборачивают CLI (GitHub, деплой), заменять скиллом поверх CLI.
- Перед сменой этапа сохранять состояние в файл и начинать с чистого контекста. Это делает твой `session-handoff`.
- Субагенту передавать цель, а не только запрос. Его ответ проверять и при необходимости переспрашивать, не больше 3 кругов.

**Карты кода (`doc-updater`)**: `docs/CODEMAPS/INDEX.md` плюс файл на каждую область, в каждом дата обновления, точки входа, таблица «модуль → назначение → зависимости», не больше 500 строк. Генерировать из кода, а не писать вручную.

**Уборка конфигурации (`config-gc`)**: раз в месяц просматривать `~/.claude` (скиллы, хуки, память, разрешения). Сначала мягкое отключение (перенос в архив), по одному пункту с подтверждением, всё записывать в журнал.

**Что это значит для MAZE2027 (замеры)**
- Каждая сессия грузит около 14,6 тыс. символов: проектный `CLAUDE.md` 7,6k, глобальный 4,3k, индекс памяти 2,7k. Это нормально, раздувать нельзя.
- `docs/robot_code_map.md` (86 строк, правка 19.10) не упоминает 49 модулей `pi/`, и `CLAUDE.md` на неё не ссылается. Claude каждый раз ищет код заново.
- Крупные файлы: `pi/oled.py` 1925 строк, `pi/victim_web.py` 795, `pi/dataset_web.py` 767, `sim/maze_sim.py` 761.
- Мусор в корне: `full104.jpg`, `full60.jpg`, `logs/`, `.claude/launch.json.tmp`.

## 3б. Общие практики: GitHub и официальная документация

**Официальная документация Anthropic** (code.claude.com/docs: costs, memory):
- `CLAUDE.md` держать короче 200 строк. То, что нужно только части кода, выносить в `.claude/rules/*.md` с полем `paths`. Если YAML в правиле сломан, оно грузится всегда.
- Импорт `@file` упорядочивает текст, но токены не экономит.
- Редкие процедуры оформлять скиллами: они грузятся только по вызову.
- Шумный вывод (тесты, сборка, логи) отдавать субагентам, чтобы в основной контекст вернулась только сводка.
- Между несвязанными задачами `/clear`, на границе этапа `/compact <что сохранить>`.
- `CLAUDE.md` для Claude только контекст, а не жёсткий запрет. Надёжно запрещать можно хуком PreToolUse.
- Память: грузятся первые 200 строк или 25 КБ `MEMORY.md`.

**Карты репозитория**
- aider repo map: граф «файл → символы → зависимости», ранжированный, около 1 тыс. токенов. Строится автоматически.
- codemap (VisualFinesse): детерминированный генератор `CODEBASE_STRUCTURE.md` без LLM. Автор отказался от LLM-сводок, потому что они устаревают.
- Схема «карта по папкам + хук после правки пересобирает изменённые части» встречается в блогах. Готовой библиотеки нет.
- repomix — упаковка всего репозитория в один файл. Это не карта, для работы внутри Claude Code вредно: съедает контекст.

**Минимальный код** — правила в духе Карпаты: минимум кода без спекуляций, если вышло 200 строк, а можно 50, переписать, трогать только нужное, убирать только свой мусор, новые зависимости только с вопросом. У тебя в `CLAUDE.md` это уже есть почти дословно. Оригинальный репозиторий не подтвердился, поэтому ставить с зеркал не стоит.

**Учёт токенов**: встроенный `/usage` (Claude Code), `ccusage` (ryoppippi) по локальным логам.

**Структура папок**: авторитетных исследований нет, только блоги. Советуют одно и то же: папки по фичам, тесты рядом, файлы по 200–400 строк.

- Свежесть: проверка в существующем хуке `pi_tests.py` или отдельный тест, который падает, если в карте нет нового модуля.

**2. Правила по путям** (`.claude/rules/`): `pi-python.md` (`paths: pi/**, sim/**`) и `esp-idf.md` (`paths: src/**, include/**`). Вынести туда разделы из `CLAUDE.md`, которые нужны только одной половине.

**3. Глобальные правила чистоты кода** (новый раздел в `~/.claude/CLAUDE.md`, 8–10 строк, для всех проектов): файл до ~400 строк, функция до ~50, ранний `return`, константы вместо чисел, ошибки не глотать, папки по фичам, тесты рядом. Не создавать отчёты, `*_v2`, временные скрипты в корне: временное только в scratchpad. Новые зависимости только с вопросом.

**4. Хук-«уборщик» (не удаляет, только предупреждает)**: PreToolUse на `Write`, если новый файл создаётся в корне репозитория или называется `*_new.*`, `*_v2.*`, `*.bak`, `test_tmp*`, `REPORT*.md`. Хук просит подтвердить, нужен ли файл.

**5. Глобальные агенты** (идеи из ECC, адаптированные):

- `code-simplifier` (Sonnet): упрощает только недавно изменённый код, поведение не меняет, сверяется с правилами из п. 3.

**6. Ежемесячная уборка конфигурации**: скилл `config-gc` по мотивам ECC — пройтись по скиллам, хукам, памяти и разрешениям, отключать мягко, по одному, с журналом.

**7. Уборка проекта** (по одному пункту с твоим подтверждением): `full104.jpg`, `full60.jpg`, `logs/`, `.claude/launch.json.tmp`, картинки и html в `docs/`. Разбиение `pi/oled.py` (1925 строк) — только если сам захочешь, отдельной задачей.
