# Промпт: ускорение и надёжность алгоритмов nav.py

Отвечай по-русски. Код в чат не выводи — пиши в файлы, в чате объясняй словами.
Сначала прочитай `docs/prompts/next-sim-scoring.md`: каждую правку nav.py проверять
в симуляторе «было/стало» (`sim/night.py`), сначала на 32 лабиринтах × шум 0/1/2.

## Контекст

Робот AZcrab (RCJ Rescue Maze 2026): Raspberry Pi 5 + ESP32-S3, лидар LD19 на 130 мм,
две боковые камеры (YOLO), датчик цвета APDS9960 на переднем бампере (90 мм впереди
центра), BNO085 (gyro-integrated rotation vector, без магнитометра).
`pi/nav.py` — навигация: клетки 300 мм, BFS до ближайшей непосещённой клетки
(`find_frontier_path`), проезд прямых без остановок по плану (`runplan`, `corridor.py`),
стоя — замер 4 стен (`_measure_cell`, голосование `vote_wall`), повороты на месте
(~0.96 с), доводка у стены, возврат на старт BFS (`return_to_start`).
Регламент: `docs/rules/RCJRescueMaze2026-draft.txt`.

Правила проекта (обязательно):
- **Заезд кончается только на старте.** Никаких FATAL-выходов: связь/моторы — ждать
  (`wait_for_robot`, фазы `wait_motors`/`wait_link` на пульте), путь домой — искать
  с ослаблением мягких запретов (`find_home_path`), чёрные (`_black_cells`) — жёсткие.
- Датчик цвета впереди: клетка под датчиком — `runplan.sensor_cell`,
  `COLOR_SENSOR_FWD_CM = 9.0`.

## Задачи (по порядку, каждая — отдельно, с прогоном «было/стало»)

1. **Синие плитки — заезжать по одному разу.** Регламент 5.6.6: 30 очков за первый
   визит, −10 за каждый повторный визит той же плитки; 5.6.12: +10 за каждую успешную
   синюю в бонусе за выход; 3.2.5b/5.5.1c: стоять 5 с подряд, иначе LoP. Сейчас BFS
   и путь домой синие не обходят, стоянка 6.0 с (`BLUE_STOP_S`). Нужно: после первого
   визита синяя клетка — очень дорогая для маршрутов (обходить, если есть путь), стоянка
   ~5.3 с (как у меток), учесть, что визит = больше половины робота на плитке (5.4.4).
2. **Дейкстра по времени вместо BFS по клеткам** (`runplan.bfs_path`, выбор цели
   разведки и путь домой): цена прямо ~0.55 с/клетку, поворот 90° ~1 с, разворот ~2 с,
   бугорок дороже, повторная синяя — см. п.1. Сохранить приоритет стороны при равной цене.
3. **Лимит 8 минут.** Сейчас nav.py про него не знает. Оценивать время до старта по
   Дейкстре и уходить домой с запасом — бонус за выход (п.1 и 10×метки) теряется, если
   не вернулся.
4. **Курс по стенам (Manhattan)**: из каждого оборота лидара — отрезки стен
   (split-and-merge/RANSAC), общее направление по модулю 90°, плавная поправка курса
   гироскопа. Главная причина потерь положения в симуляторе при сильном шуме — уход
   гироскопа.
5. **Не ждать лидар стоя** (11% времени): брать обороты с подъезда или один оборот.
6. **Карта дальних стен**: голосовать по видимым лидаром рёбрам клеток на 1–2 м.
7. Позже, отдельным решением: положение по карте (сопоставление скана с сеткой 300 мм),
   повороты на ходу вместо стоп-поворот-разгон (повороты — 25% времени), порядок
   разведки (добирать тупики рядом), выдача комплектов параллельно с миганием (сначала
   проверить регламент 4.x/5.x).

## Открытые вопросы

- Защита датчика цвета по наклону (`PITCH_COLOR_GUARD_DEG` = 3°, в обе стороны) слепит
  его на бугорке у чёрной/синей. Ждём замер на роботе: C на белой и синей ровно / нос
  вверх / нос вниз на бугорке 1 см. Без цифр защиту не менять.
- Ветка «синяя после решения» в `drive_cells`: подозрение на сдвиг счёта клеток —
  проверить отдельным тестом.
