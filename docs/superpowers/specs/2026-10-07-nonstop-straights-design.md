# Остановки только на поворотах — дизайн

Дата: 2026-10-07. Статус: согласован по секциям, ждёт ревью спецификации.

## Зачем

Сейчас `flood_fill_run`/`return_to_start` зовут `drive_cells(1)`: робот встаёт
в центре каждой клетки (замер стен стоя, плитка, скан камерами). Нужно
останавливаться только там, где нужен поворот (робот разворачивается на месте),
а прямые участки — и по известным, и по новым клеткам — проезжать на крейсерской
скорости. Метки на прямых ловит наблюдатель (уже сделан).

Прежний режим без остановок решал «поворачивать ли» по одному боковому скану за
`DECIDE_LEAD_MM` до центра клетки и давал пропущенные повороты (комментарий у
`PER_CELL_STOP`). Новый режим решает по стенам следующей клетки, собранным на
подходе, и при неуверенности останавливается.

## Как это делают в micromouse (взято за основу)

- Фиксированная точка решения в каждой клетке: UKMARS mazerunner ждёт
  `FULL_CELL - 10`, читает стены следующей клетки (диагональные датчики видят их
  заранее), обновляет карту, считает flood fill; прямо — едет дальше без
  остановки, иначе поворот.
- Координата хода непрерывна (`adjust_position(-FULL_CELL)` при переходе
  клетки), без обнулений.
- Обрывы боковых стен («столбики» на границе клеток) поправляют одометрию вдоль
  хода — без этого на длинной прямой копится ошибка.

## Неизменное

- Скорости и пороги (`MOVE_*`, `BRAKE_DECEL_CMS2`, `MARK_BRAKE_DECEL_CMS2`,
  `SIDE_THRESH`, `WALL_THRESH`, `DECIDE_LEAD_MM`, маски лидара) не меняются.
- Протокол ESP↔Pi и прошивка не трогаются.
- Поворот — на месте, стоя в центре клетки; там же — замер стоя, плитка, скан
  камерами (`arrive`), как сейчас.
- Горки, препятствия, бампер, `wall_close`, чёрная плитка, остановка на метку —
  поведение `drive_cells` прежнее.

## Геометрия лидара (ограничение)

Углы в системе робота: 0° — вперёд, по часовой, 90° — правый борт. Маски
`walls.MASKS` закрывают: ручки 90±12 / 270±12, леску 105±7 / 255±7, передние
стойки 25±10 / 335±10, зад 180±55. Поэтому боковую стену на 150 мм вбок лидар
видит впереди только в секторе 35°..78° (и зеркально 282°..325°) — это
~32..214 мм вперёд от лидара. Средняя часть боковой стены следующей клетки
(±100 мм от её центра) попадает в поле зрения за ~200 мм до точки решения: 2–3
оборота лидара (10 Гц, 55 см/с), ~40 точек на сторону за оборот (точки по 1°).
Лидар считается стоящим в центре робота.

## Компоненты

1. **`pi/lidar_proc.py`** — к сообщению оборота добавляется `"pts"`: точки
   коридора в системе робота `[x_fwd_mm, y_right_mm]` (целые), уже прошедшие те
   же фильтры, что `walls.measure` (контур корпуса, маски, леска,
   `without_unsupported_rope_edges`), в коридоре `-100 ≤ x ≤ 600`,
   `60 ≤ |y| ≤ 320`; и `"trev"` — длительность оборота (с). Фильтрация точек
   выносится из `walls.measure` в `walls.filtered(rev)` (общая для обоих).
2. **`pi/corridor.py`** (новый, чистая логика под тестами):
   - `to_path_frame(pts, traveled_mm, yaw_err_deg)` → точки в системе пути
     `(X вдоль хода от центра исходной клетки, Y вбок, вправо > 0)`, с поворотом
     на ошибку курса.
   - `visible_span(x_robot, seg_lo, seg_hi, side, masks)` → сколько мм отрезка
     боковой стены (на 150 мм вбок) видно с позиции `x_robot` (не закрыто
     масками, в пределах 600 мм).
   - `CellSides` — накопитель по клеткам впереди: для клетки с центром `c` и
     стороны — точки в полосе `|X-c| ≤ 100`, `100 ≤ |Y| ≤ 210` и видимая длина
     (объединение интервалов). Итог стороны: `True` (стена) — ≥ 8 точек и их
     поперечный разброс (межквартильный) ≤ 20 мм; `False` (проход) — видимо
     ≥ 120 мм и точек ≤ 2; иначе `None` (не уверен).
   - `post_error(...)` — конец/начало боковой стены вдоль хода против
     ожидаемой границы клетки `c ± 150`: ошибка или `None`, если не ближе 40 мм.
3. **`pi/runplan.py`** (новый, чистый): `first_step(start, hdg, open_dirs,
   next_cell, goal_test, side_order)` — BFS из `nav.find_path_bfs`,
   параметризованный функциями; `nav.find_path_bfs` становится обёрткой. Плюс
   `go_straight(...)` — решение «прямо/стоп» для клетки N с временными стенами.
4. **`pi/watch_logic.py`** — приписывание метки клетке на ходу обобщается на
   поездку из нескольких клеток: индекс клетки по пути
   `k = floor((traveled_mm + 150) / 300)`.
5. **`pi/nav.py`**:
   - `_lidar_thread` кладёт `(t_оборота, pts)` в очередь последних оборотов;
   - `drive_cells(max_cells, …, plan=…)`: точка решения прежняя
     (`rem ≤ DECIDE_LEAD_MM`), но решение задаёт `plan.decide(k, walls)`
     вместо «справа открыто / спереди стена»; на ходу — накопление `CellSides`,
     поправка по столбикам, плитки, вызов `plan.passed(k, walls, tile)` при
     проезде центра клетки без остановки;
   - `flood_fill_run`/`return_to_start` зовут `drive_cells` с большим
     `max_cells` и планом; клетки, проеханные без остановки, записываются в
     карту по ходу, `arrive` (замер стоя, скан камерами) — только в клетке
     остановки.

## Решение в клетке

Точка решения — `rem ≤ DECIDE_LEAD_MM` (110 мм) до центра следующей клетки N
(тормозной путь с 55 см/с: 50 мм + упреждение 27 мм — запас есть).

- N посещена — решение по карте: следующий шаг маршрута из N (BFS: до фронтира
  при разведке, до старта при возврате) совпадает с курсом → прямо.
- N новая — временные стены N: справа/слева — `CellSides`, спереди — голоса
  переднего луча (как сейчас: `f − остаток`, `wall_present(…, WALL_THRESH)`,
  большинство из ≥ 2 оборотов), сзади — проход. Любая сторона `None` → стоп.
  Иначе BFS из N по карте с временными стенами N: первый шаг = курс → прямо,
  иначе стоп в центре N.
- Синяя плитка над N (датчик цвета на ходу) → стоп в центре N (тормозного пути
  хватает: синяя видна с ~15 мм за границей N, до центра ~135 мм).
- Серебряная над N → N — чекпоинт, без остановки.

## Проезд клетки без остановки

При прохождении центра N (путь ≥ центр N): N в `_visited`; стены N голосуются в
карту (`vote_wall`) из `CellSides` (стороны с `None` не голосуют), спереди и
сзади — проход по факту (`open_edge`); чекпоинт — если серебряная;
`_write_state`. Таймер клетки перезапускается (как в нынешнем режиме).

## Поправка по столбикам

Из точек полосы видно, где боковая стена начинается/кончается вдоль хода.
Ожидаемое место — граница клетки `c ± 150`. Если ошибка `|e| ≤ 40` мм —
`boundary_cm` и центры клеток впереди сдвигаются на `e/2`, не чаще раза на
клетку; лог `[odo] столбик …`. Больше 40 мм — только лог.

## Ошибки и откат

- Нет точек лидара (процесс перезапускается), «не уверен» по любой стороне N →
  стоп в центре N, дальше как сейчас (замер стоя).
- Пауза/подъём/связь — как сейчас.
- `plan` не передан (`challenge.py`, старые вызовы) → прежнее поведение
  `drive_cells(1)`.

## Логи

На каждую клетку прямого пробега: `→ кл.(x,y): R=есть(14т,180мм)
L=нет(1т,150мм) F=нет(0:3) → прямо` (точки, видимая длина, голоса переднего
луча). `не уверен → стоп`, `[odo] столбик …`, итог поездки: клеток, остановок.
