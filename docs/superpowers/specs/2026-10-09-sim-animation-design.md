# Анимация прогона симулятора — дизайн

Дата: 2026-10-09. Статус: согласован по секциям, ждёт ревью спецификации.

## Зачем

Отладка `pi/nav.py`: видеть по кадрам, как робот едет по полигону с горками и
препятствиями, почему в клетке решил «прямо» или «стоп», где ошибся в карте,
как сработали ассист, столбики, бампер. Главное — точность и подробность, а не
красота. Данные берутся из существующего симулятора (`sim/maze_sim.py`), где
крутится настоящий `nav.py`.

## Неизменное

- Логика `pi/nav.py`, `pi/corridor.py`, `pi/runplan.py`, прошивка `src/`,
  скорости и пороги не меняются.
- `python3 sim/run_scenarios.py` без флагов ведёт себя как сейчас: тот же вывод,
  те же `sim/logs/<имя>.log`, «ВСЕ СЦЕНАРИИ ЧИСТЫЕ».
- Модель лидара и движения в `maze_sim.py` не меняется — только добавляются
  точки, где регистратор получает данные.
- Ничего не публикуется: просмотрщик — локальные файлы на Маке, работает без
  интернета и без сервера.

## Компоненты

1. **`sim/maze_sim.py`** — необязательный регистратор `Sim.rec` (по умолчанию
   `None`, тогда поведение прежнее). Вызовы:
   - каждый шаг модели (5 мс) — поза и состояние;
   - каждый оборот лидара — лучи и точки коридора (то, что `_scan` уже считает);
   - `Sim.write` — сырые команды; `B` фиксируется как отдельный режим до того,
     как модель сведёт его к `M 0,0`.
2. **`sim/trace.py`** — чистые функции (под тестами) и класс `Recorder`:
   - разбор строки лога в событие;
   - прореживание позы;
   - сериализация мира (стены, сэмплирование рельефа), правда по рёбрам клеток
     с учётом этажа, снимки карты, сборка детерминированного JSON.
3. **`sim/viewer/build.py`** — вставляет JSON в `sim/viewer/template.html`, пишет
   страницы сценариев и оглавление.
4. **`sim/viewer/template.html`** — страница просмотрщика (CSS и JS внутри,
   three.js из `vendor/`).
5. **`sim/viewer/vendor/three.module.js`** — локальная копия three.js
   фиксированной версии, закоммичена; версия и источник — в комментарии шаблона.
6. **`sim/run_scenarios.py`** — флаг `--html`.
7. **`sim/tests/`** — тесты stdlib unittest.

## Запись трассы

### Поза

На каждом шаге модели регистратор получает: `t, x, y, z` (высота рельефа под
центром робота), `theta` (° по часовой от севера), `pitch`, `vl, vr` (см/с),
режим `M`/`T`/`B` и уставки (`l, r, cap`), `bumped`, расстояние до передней
стены `nav._state["wall"]["front"]`.

Прореживание (чистая функция): кадр раз в 20 мс (50 Гц) плюс обязательные
кадры — на смене режима команды, на смене `bumped`, в момент каждой строки лога.
Первый и последний кадры сохраняются всегда.

### Лидар

На каждый оборот: `t`, поза в момент оборота, все лучи — мировые координаты
конца `(x, y, z)` и признак «стена» / «пол или рельеф»; точки
`corridor_points` (система робота) переведены в мировые `(x, y)`.

### Лог

Stdout во время прогона подменяется писателем, который режет текст по `\n` и
`\r` и запоминает каждую непустую строку с `sim.t`. Полный текст по-прежнему
пишется в `sim/logs/<имя>.log` без изменений.

Разбор строки → событие `{t, type, text, ...поля}`. Типы:

| тип | строка лога (пример начала) | поля |
|---|---|---|
| `step` | `─── (0,0) N → E  0/30 ───` | клетка, курс из, курс в |
| `decide` | `→ кл.(1, 0): R=есть(68т,175мм) L=… F=… → прямо (новая)` | клетка, R/L/F (есть/нет и числа), `straight`/`stop`, причина |
| `post` | `[odo] столбик left у границы кл.1: …` | сторона, номер клетки, поправка |
| `progress` | `кл.2 ост. 110мм  yaw=… spd=55` | номер клетки, остаток, spd |
| `brake` | `торможение с 55см/с: …` | скорость |
| `at_wall` | `у стены: f=147мм` | f |
| `turn` / `turn_done` | `поворот +90° …` / `итог yaw=…` | угол / ошибка |
| `move` | `движение  курс=127°` | курс |
| `ramp_detect` | `горка: pitch=…, момент NA …` | pitch, ток |
| `ramp_up` / `ramp_down` | `ГОРКА ВВЕРХ (+13.0°) …` | угол |
| `ramp_measure` | `горка: 612мм по уклону …` | длина, уклон, высота |
| `ramp_done` | `⛰ ГОРКА вверх: …, (2,1) → (2,1004), …` | откуда, куда |
| `not_ramp` | `не горка: …` | — |
| `obstacle` | `препятствие #1: pitch=…` | номер, pitch |
| `bumper` | `БАМПЕР (both) на …мм` | сторона, путь |
| `backoff` | `откат …мм …` | мм |
| `align` | строки с `[выр]` | — |
| `other` | всё прочее | только `text` |

Ассист (режим `T`) берётся и из событий `ramp_detect`/`obstacle`, и из позы
(режим команды). Нераспознанные строки не теряются — тип `other`.

### Снимки карты

`nav._write_state` (в симуляторе — заглушка) оборачивается: при каждом вызове
снимаются `_maze`, `_visited`, `_ramps`, `_blocked` и фаза; снимок попадает в
трассу, только если карта изменилась. Последний снимок — в конце прогона.

### Мир

- Стены: `(x0, y0, x1, y1, z0, z1)` как есть.
- Рельеф: функции высоты сэмплируются сеткой 10 мм по прямоугольнику куска.
  Постоянная высота → плоский кусок (остров, бугорок) с высотой `h`; иначе —
  наклонный (горка): высоты по углам и направление подъёма (N/E/S/W).
- Правда по рёбрам клеток для каждого этажа: для клетки `(cx, cy)` этажа `L`
  мировая клетка `(cx, cy - L*1000)`; ребро — стена, если на середине ребра
  есть стена мира, чей `z0..z1` перекрывает высоту пола клетки + 40 мм
  (обобщение `wall_truth`, которое сейчас знает только нижний этаж).

### Формат

Один JSON на сценарий: `meta` (имя, статус, итог прогона), `world`, `truth`,
`poses`, `scans`, `events`, `maps`. Числа округлены: мм — до 0,1, градусы — до
0,01, время — до 1 мс. Ключи отсортированы, без времени запуска и путей.
Повторный прогон даёт байт-в-байт тот же файл. Ожидаемый объём — 1–2 МБ на
сценарий.

## Просмотрщик

### Устройство

Страница на сценарий `sim/viewer/<имя>.html` и оглавление
`sim/viewer/index.html`. Трасса вставлена в страницу как
`<script type="application/json">` (браузер не даёт `file://`-странице читать
соседние файлы); `</` внутри данных экранируется. three.js подключается как
ES-модуль из `vendor/` через import map. Первым делом проверить, что Safari и
Chrome грузят модуль по относительному пути с `file://`; если нет — three.js
вставляется прямо в каждую страницу. Других библиотек нет: вид сверху, карта и
графики — canvas 2D. Цвета — переменные CSS, тёмная тема по
`prefers-color-scheme`. Целевой экран — Мак, ширина от 1440 px.

### Раскладка (всё на одном экране)

- **Панель управления (шапка):** выбор сценария (ссылки на соседние страницы),
  пуск/пауза (пробел), скорость 0,25–8×, шкала времени с метками событий,
  «← / → событие» с фильтром типа (решение, горка, столбик, бампер, ассист),
  чекбоксы слоёв.
- **Вид сверху (верх слева):** стены, тон по высоте; горки — градиент высоты и
  стрелка подъёма; острова верхнего этажа; бугорки и кирпичи; корпус 193×125 мм
  в масштабе с носом и колёсами; след траектории, цвет по скорости; веер лучей
  последнего оборота (пол/рельеф — бледные, стены — яркие) и точки коридора;
  метки решений в клетках (зелёная — прямо, красная — стоп), подсказка с
  полным текстом решения при наведении; значки столбиков, ассиста, бампера.
  Колесо — масштаб, перетаскивание — сдвиг, кнопка «следить за роботом».
- **3D (верх справа):** стены и горки в объёме, острова, корпус-коробка с носом
  и колёсами, наклон по `pitch`, лучи последнего оборота. Камера сзади-сверху
  следует за роботом; мышью — облёт, клавишей — вернуть следование.
- **Карта глазами робота (середина справа):** клетки этажа из последнего
  снимка на момент бегунка. Стена nav, совпадающая с правдой, — сплошная;
  стена у nav, которой нет в мире, — красная; стена в мире, у nav проход, —
  оранжевый пунктир; неизвестно — серое. Посещённые клетки залиты, горки —
  стрелкой, заблокированные — штриховкой. Этаж 0/1 — кнопками, по умолчанию —
  этаж робота.
- **Профиль высоты и графики (низ, общая ось времени с бегунком):** профиль z
  вдоль пройденного пути с курсором; скорость (vl, vr, средняя, уставка);
  pitch; полоса режима M/T/B цветом; расстояние до передней стены.
- **Консоль лога (справа во всю высоту):** строки со временем, текущая
  подсвечена и прокручивается в зону видимости, клик по строке — перемотка;
  события подкрашены по типу, `progress` можно скрыть.

### Оглавление

Таблица сценариев: имя (ссылка), статус, время модели, клеток посещено, горки,
ошибки карты, упирался ли в стены.

## Генерация

`python3 sim/run_scenarios.py --html [имя ...]` прогоняет сценарии с
регистратором, пишет `sim/viewer/data/<имя>.json`, `sim/viewer/<имя>.html`,
`sim/viewer/index.html` и в конце печатает путь к оглавлению. Проверки карты и
итоговая строка — как без флага. В `sim/.gitignore`: `viewer/data/` и
`viewer/*.html` с исключением `!viewer/template.html`.

## Тесты (`sim/tests/`, `python3 -m unittest discover -s sim/tests`)

- Разбор лога: реальная строка на каждый тип из текущих логов, строки с `\r`,
  нераспознанная → `other`.
- Прореживание: частота, обязательные кадры (смена режима, бампер, события),
  первый и последний.
- Сэмплирование рельефа: плоский остров, горка (направление и высоты), бугорок.
- Правда по рёбрам: нижний этаж совпадает со старым `wall_truth`, верхний этаж
  в `ramp_world`.
- Детерминированность: `flat` дважды — одинаковый JSON.
- Сборка HTML: данные вставлены, `</script>` в данных экранирован.

## Проверка перед «готово»

1. `python3 -m unittest discover -s pi/tests` и `-s sim/tests` — зелёные.
2. `python3 sim/run_scenarios.py` — «ВСЕ СЦЕНАРИИ ЧИСТЫЕ», логи совпадают с
   логами до изменений.
3. `python3 sim/run_scenarios.py --html` — страницы собраны.
4. pyright — не больше 16 ошибок.
5. `open sim/viewer/index.html`: в Chrome и Safari анимация идёт, 3D рисуется,
   в консоли браузера нет ошибок.

## Коммиты

Один шаг — один коммит: хуки в модели; разбор лога; прореживание и мир;
сериализация и флаг `--html`; three.js в vendor; шаблон (по панелям);
оглавление.
